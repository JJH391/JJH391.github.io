GitHub Actions의 `schedule` cron으로 "3일마다 한 번"을 표현하려고 했는데, cron 문법 자체에는 그런 간격이 없었습니다. 매일 실행하는 트리거를 걸고, 스크립트 안에서 마지막 실행 시각을 비교해 건너뛰는 방식으로 바꿨습니다.

## cron으로 "3일마다"가 안 되는 이유

cron의 day-of-month 필드에 `*/3`처럼 쓰면 매달 1일부터 3일 간격으로 돈다는 뜻이 됩니다. 1, 4, 7, 10일처럼 돌다가 월이 바뀌면 다시 1일부터 세기 시작합니다. 그래서 이번 달 마지막 실행일과 다음 달 첫 실행일 사이의 간격이 3일이 아니게 되는 경우가 생깁니다. day-of-month 기반 표현으로는 "지난번 실행으로부터 정확히 3일 뒤"를 보장할 수 없습니다.

## 매일 실행 + 시각 비교로 대체

대신 워크플로는 매일 실행하도록 걸고, 실제로 게시할지는 스크립트가 결정합니다.

```yaml
on:
  schedule:
    - cron: "40 11 * * *"
jobs:
  publish:
    runs-on: ubuntu-24.04
```

`40 11 * * *`는 UTC 기준이라 한국 시간으로는 20:40입니다. 실행될 때마다 `posted.json`에 저장된 마지막 게시 시각을 읽어서, 3일(여유 2시간을 뺀 기준)이 지나지 않았으면 그냥 종료합니다.

```python
last = dt.datetime.fromisoformat(state["posted"][-1]["at"])
if now - last < dt.timedelta(days=3, hours=-2):
    return  # skip
```

`timedelta(days=3, hours=-2)`는 3일에서 2시간을 뺀 값, 즉 실제 기준은 2일 22시간입니다. 매일 같은 시각에 실행되는 트리거가 몇 분~몇 시간 늦게 돌 가능성을 감안해 기준을 살짝 당겨 잡은 값입니다.

## 실행 로그에 뜬 ubuntu-latest 변경 공지

워크플로 실행 로그에 다음 공지가 표시됐습니다.

> The ubuntu-latest label will migrate to Ubuntu 26 beginning October 19, 2026.

`runs-on: ubuntu-latest`를 쓰고 있으면 2026년 10월 19일부터 실행 환경이 Ubuntu 26으로 바뀐다는 공지입니다. 환경이 바뀌면 사전 설치된 패키지 버전이나 폰트 경로 같은 세부 사항이 달라질 수 있어서, `runs-on`을 `ubuntu-24.04`로 명시해 버전을 고정했습니다.

같은 로그에 "Node.js 20 is deprecated..." 경고도 함께 표시됐는데, 이 경고는 동작 자체에는 영향을 주지 않는 것으로 확인했습니다.

## 정리

- cron의 day-of-month 기반 `*/N` 표현은 월이 바뀌는 지점에서 간격이 깨지기 때문에 "N일마다"를 정확히 표현하는 용도로는 쓸 수 없다.
- 대안은 매일 실행 트리거를 걸고, 스크립트 안에서 마지막 실행(게시) 시각을 저장해두고 비교해 건너뛰는 방식이다.
- `runs-on: ubuntu-latest`는 실행 시점의 최신 Ubuntu로 자동 이동하므로, 환경이 바뀌는 시점(2026년 10월 19일부터 Ubuntu 26)을 로그 공지로 미리 확인할 수 있고, 버전을 고정하려면 `ubuntu-24.04`처럼 구체적인 버전을 명시해야 한다.
