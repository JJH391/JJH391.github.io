공격 탐지 통계를 공개 페이지로 만들어뒀는데, 숫자를 다시 들여다보니 대부분이 실제 공격이 아니라 제가 직접 돌리던 모의해킹 스크립트와 자동 플레이 봇이 만든 기록이었습니다.

## 무엇이 있었나

이벤트 기록 코드를 확인해보니 탐지 유형과 시각만 저장할 뿐, 어디서 들어온 요청인지는 구분하지 않고 있었습니다. 그 결과 다음 세 가지가 전부 같은 집계에 섞여 들어갔습니다.

1. 실제 방문자가 보낸 공격성 요청
2. 셀프 모의해킹 스크립트가 보내는 테스트 요청 (1회 실행에 약 100건)
3. 자동으로 완주하는 플레이 봇이 만드는 탐지 기록

공개 페이지에 노출되는 숫자가 사실상 "실제 공격 건수"가 아니라 "제가 테스트한 횟수"에 더 가까운 상태였습니다.

## 원인

로그를 남기는 지점에서 요청의 출처를 구분하는 어떤 필드도 없었습니다. 탐지 로직이 호출되면 무조건 기록하고 공개 집계에 더하는 구조였기 때문에, 테스트 트래픽과 실제 트래픽을 나중에 분리할 방법이 없었습니다.

## 해결

테스트 스크립트에만 있는 비밀 토큰을 `X-Fortress-Selftest` 헤더로 보내도록 하고, 서버에는 토큰 원문이 아니라 그 SHA-256 해시만 비밀 저장소(`SELFTEST_HASH`)에 저장했습니다. 요청이 들어오면 헤더 값의 해시를 계산해 저장된 해시와 비교하고, 일치하면 공개 집계에서 제외합니다.

```js
export async function isSelfTest(request, env) {
  const t = request.headers.get('X-Fortress-Selftest');
  if (!t || typeof env.SELFTEST_HASH !== 'string' || env.SELFTEST_HASH.length < 43 || t.length > 100) return false;
  return safeEqual(b64u(await sha256(t)), env.SELFTEST_HASH);
}
```

워커가 이 판정을 끝낸 뒤, 게임 서버 역할을 하는 Durable Object로는 판정 결과만 `X-FX-Self` 헤더에 담아 넘깁니다. 이때 브라우저가 같은 이름(`X-FX-Self`)의 헤더를 직접 보내 판정을 흉내 낼 수 없도록, 워커가 자체적으로 다시 설정하기 전에 클라이언트가 보낸 동일 이름의 헤더를 먼저 지웁니다.

로그에 남기는 내용도 같이 손봤습니다. 한 줄에 시각, 방문자 번호(`HMAC(비밀키, 날짜+IP)`의 앞 6자리), 요청 틀, 탐지 유형, 실제 처리 결과만 남기고, 요청 원문이나 IP, 쿠키 값은 저장하지 않도록 했습니다.

## 확인한 방법

모의해킹 스크립트에 "실행 전후 공개 집계 값이 거의 그대로인지" 확인하는 항목을 추가했습니다. 실제 사이트에 적용한 뒤 확인한 값은 다음과 같습니다.

| 시점 | 실행 전 | 실행 후 |
| --- | --- | --- |
| 1차 확인 | 0 | 0 |
| 2차 확인 | 21 | 21 |
| 3차 확인 | 28 | 28 |

모의해킹 스크립트를 여러 번 돌려도 공개 집계 숫자가 그대로 유지되는 것을 확인했습니다.

## 정리

- 탐지 로그에 요청 출처 구분이 없으면, 자체 테스트 트래픽과 실제 트래픽이 공개 통계에 그대로 섞인다.
- 비밀 토큰을 헤더로 보내고 서버에는 토큰 원문 대신 해시만 저장해 비교하면, 토큰이 유출돼도 저장소 값만으로는 토큰을 복원할 수 없다.
- 클라이언트가 보낼 수 있는 헤더와 서버 내부에서만 주고받아야 하는 헤더가 이름이 같다면, 서버가 자체 값을 설정하기 전에 클라이언트가 보낸 값을 먼저 제거해야 위조를 막을 수 있다.
- 자동화된 확인 스크립트에 "공개 수치가 변하지 않는지" 같은 항목을 넣어두면, 집계 분리가 실제로 적용됐는지 매번 사람이 눈으로 비교하지 않아도 된다.
