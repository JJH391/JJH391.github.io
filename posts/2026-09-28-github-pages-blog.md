요즘 유튜브에 AI로 돈을 번다는 영상이 많이 보여서, 나도 직접 해보자는 생각으로 이 블로그를 시작했습니다. 그런데 시작하려고 보니 블로그를 어디에 만들지부터 정해야 합니다. 티스토리, 네이버 블로그, 워드프레스, Velog… 선택지가 많습니다.

조건을 **계속 0원일 것** 하나로 잡으면 후보가 확 줄어듭니다. 처음만 무료고 나중에 돈을 받는 곳은 빠지니까요. 그 기준으로 GitHub Pages를 골랐습니다.

## 왜 정적 사이트인가

블로그 서비스는 크게 둘로 나뉩니다.

- **동적** — 워드프레스처럼 서버가 방문자가 올 때마다 페이지를 만들어 보냅니다. 서버가 필요하니 돈이 듭니다.
- **정적** — HTML 파일을 미리 만들어두고 그대로 보냅니다. 파일을 올려둘 곳만 있으면 됩니다.

블로그 글은 한 번 쓰면 잘 안 바뀌고, 방문자마다 다른 화면을 보여줄 일도 없습니다. 그러면 정적으로 충분합니다. 그리고 정적이면 **방문자가 100명이든 10만 명이든 비용이 0원**입니다.

## GitHub Pages가 주는 것

GitHub 저장소에 HTML을 넣어두면 `https://아이디.github.io` 주소로 서빙해 줍니다. 무료입니다.

| 항목 | 무료 범위 |
| --- | --- |
| 저장소 크기 | 1GB 권장 |
| 트래픽 | 월 100GB |
| 빌드 | 시간당 10회 |
| HTTPS | 기본 제공 |

글 위주 블로그가 월 100GB를 넘기려면 방문자가 수십만 명은 돼야 합니다. 당분간 걸릴 일이 아닙니다.

## 생성기: 가져다 쓸까, 직접 짤까

Jekyll이나 Hugo 같은 정적 사이트 생성기를 쓰는 길이 있고, 짧은 스크립트를 직접 쓰는 길이 있습니다.

**가져다 쓰면** 빨리 시작합니다. 대신 테마 구조를 모르는 채로 CSS를 더듬게 되고, 뭔가 깨졌을 때 어디를 봐야 할지 모릅니다.

**직접 짜면** 처음에 반나절이 듭니다. 대신 전부 읽을 수 있는 코드가 남습니다. 하는 일은 이 다섯 개가 전부입니다.

1. `posts/` 폴더의 마크다운 파일을 읽는다
2. 맨 위 frontmatter에서 제목·날짜·태그를 꺼낸다
3. 본문을 마크다운 파서로 HTML로 바꾼다
4. 템플릿에 끼워서 `docs/`에 쓴다
5. 목록 페이지, 태그 페이지, `sitemap.xml`, RSS도 같이 만든다

외부 의존성은 마크다운 파서 하나면 됩니다.

실제로 짜보니 코드 자체보다 진도가 더뎠던 이유는 따로 있었습니다. AI 도구를 같이 쓰면서 작업했는데 한 번에 쓸 수 있는 양에 한도가 있다 보니, 몰아서 빠르게 끝내지 못하고 나눠서 진행해야 했습니다. 하루 반나절이면 될 일이 며칠에 걸쳐 나뉘어 진행된 셈입니다.

## 검색에 잡히려면 따로 해야 하는 것

만들어놓기만 하면 아무도 안 옵니다. 이건 별도 작업입니다.

- **`sitemap.xml`** — 어떤 글이 있는지 알려주는 목록. 빌드할 때 자동 생성되게 해두면 편합니다
- **Google Search Console** 에 사이트를 등록하고 sitemap 제출
- **네이버 서치어드바이저** 에도 같은 작업. 한국어 글이면 네이버 유입이 무시 못 합니다
- **`<title>`과 `meta description`** — 검색 결과에 그대로 뜨는 부분
- **canonical URL** — 같은 글이 여러 주소로 잡히는 걸 막습니다

## 진짜로 드는 돈

호스팅, 빌드, HTTPS 전부 0원입니다. 딱 하나 걸리는 건 주소입니다.

기본 주소가 `아이디.github.io` 형태입니다. 자기 도메인(`example.com`)을 쓰려면 연 1~2만 원이 듭니다.

서브도메인으로 시작해도 나중에 도메인을 붙일 수 있습니다. GitHub Pages 설정에서 연결하면 되고, 주소가 바뀌어도 리다이렉트가 걸립니다. 그래서 급하지 않은 선택입니다.

저는 당분간은 `jjh391.github.io`를 그대로 쓸 생각입니다. 나중에 더 나은 방법이 보이면 그때 옮기려고 합니다.
