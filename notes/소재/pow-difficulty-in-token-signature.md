# 작업증명(PoW) 난이도를 토큰 서명에 넣어야 하는 이유

- **한 줄 요약**: 붐빌 때 PoW 난이도를 올리려면, 난이도를 토큰 서명에 포함하고 "보내는 순간의 난이도"로 다시 검사해야 쉬운 토큰 바꿔치기·미리 받아 두기를 막을 수 있다
- **무엇이 있었나**:
  1. 피드백: "사이트 전체 상한(낙서 1분 12개, 가입 시간당 200명)은 한 명이 채우면 다른 사람이 막히는 DoS 벡터".
  2. 상한에 닿으면 거절하는 대신 최근 개수에 따라 PoW 비트를 올리는 방식으로 변경.
  3. 이때 생길 수 있는 우회 두 가지를 단위 테스트로 확인: (a) 토큰 속 난이도를 16으로 고쳐 쓰기 → 서명 불일치로 400, (b) 한가할 때 받아 둔 16비트 토큰을 붐빌 때 사용 → 428(다시 계산 요구).
- **원인/설계 근거**: 토큰 형식이 `nonce.exp.sig`일 때는 난이도가 서명 밖(서버 상수)에 있어 "토큰마다 다른 난이도"를 표현할 수 없었다.
- **해결/결론**: 토큰을 `nonce.exp.bits.sig`로 바꾸고 HMAC 대상에 `bits` 포함. 검증 시 `bits < 지금 요구 난이도`면 `428 { pow, bits }`를 돌려주고, 클라이언트는 그 비트로 새 문제를 받아 한 번 더 계산.
- **코드/명령어**:

```js
const payload = `${randomId(12)}.${Date.now() + TTL_MS}.${bits}`;
const token = `${payload}.${await hmac(env, `pow:${purpose}:${payload}`)}`;
// 검증
if (bits < await powBits(env, purpose)) throw powRequired(purpose, '…', /* 새 난이도 */);
```
